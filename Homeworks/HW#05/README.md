## 4. Mathematical Formulation & Solutions

### 4.1 Underdetermined Sparse Model and Evaluation Metric

Because the dictionary $D \in \mathbb{R}^{10 \times 60}$ has more columns than rows ($N = 60 > M = 10$), the linear system $x = D s$ is **underdetermined** and admits infinitely many solutions in general. However, when $s$ is sufficiently sparse ($\|s\|_0 = N_0 = 3 < \mathrm{spark}(D)/2$), the sparsest solution to

```math
\hat{s} = \arg\min_{s \in \mathbb{R}^N} \|s\|_0
\qquad \text{subject to} \qquad
x = D s
```

is unique. Across all parts of `code/Section1.m`, the reconstruction quality of an estimate $(\hat{D}, \hat{s})$ is quantified by the **normalized Euclidean ($\ell_2$) residual error**:

```math
\mathrm{err} = \frac{\left\|x - \hat{D}\hat{s}\right\|_2}{\|x\|_2}
= \frac{\sqrt{\sum_{m=1}^{M} \left(x_m - (\hat{D}\hat{s})_m\right)^2}}{\sqrt{\sum_{m=1}^{M} x_m^2}}.
```

### 4.2 Part الف (Part 1 in Code) — Subset Selection (`Section1.m` lines 5–26)

When the exact sparsity level $N_0 = 3$ is known a priori, **Subset Selection** performs an exhaustive combinatorial search over all candidate support sets $\mathcal{I} \subset \{1, 2, \dots, N\}$ of cardinality $|\mathcal{I}| = N_0$. The total number of candidate sub-dictionaries is:

```math
\binom{N}{N_0} = \binom{60}{3} = \frac{60 \times 59 \times 58}{3 \times 2 \times 1} = 34\,220.
```

In `code/Section1.m` (lines 10–22), `combinations = nchoosek(1:size(D, 2), N_0)` generates the $34\,220 \times 3$ table of index triplets. For each candidate triplet $i \in \{1, \dots, 34\,220\}$:

1. Extract the $10 \times 3$ sub-dictionary $\hat{D}^{(i)} = D(:, \mathrm{combinations}(i, :))$.
2. Compute the least-squares coefficient vector via the Moore-Penrose pseudoinverse:

```math
\hat{s}^{(i)} = \left(\hat{D}^{(i)}\right)^\dagger x = \left(\left(\hat{D}^{(i)}\right)^T \hat{D}^{(i)}\right)^{-1} \left(\hat{D}^{(i)}\right)^T x \in \mathbb{R}^{3 \times 1}.
```

3. Evaluate the relative residual error $\mathrm{err}_i = \|x - \hat{D}^{(i)} \hat{s}^{(i)}\|_2 / \|x\|_2$.
4. Retain the solution if $\mathrm{err}_i < \mathrm{err\_thr}$ with $\mathrm{err\_thr} = 10^{-6}$.

Only a single support triplet—corresponding to columns $(3, 6, 54)$ of $D$—satisfies $\mathrm{err}_i < 10^{-6}$, yielding the exact non-zero source coefficients (Pages 1–2 of the report):

```math
\hat{S} = \begin{bmatrix} 5 \\ 7 \\ -3 \end{bmatrix},
\qquad
\mathrm{err} = 6.7605 \times 10^{-16} \approx 0,
\qquad
t_{\mathrm{exec}} = 1.084438\ \mathrm{s}.
```

**Role of knowing $N_0$:** Knowing $N_0 = 3$ is **extremely helpful** for Subset Selection. Without prior knowledge of $N_0$, the algorithm would have to search sequentially over $k = 1, 2, 3, \dots$ until the residual error falls below $\mathrm{err\_thr}$, requiring $\sum_{k=1}^{N_0} \binom{N}{k}$ pseudoinverse evaluations—which grows combinatorially and becomes computationally intractable as $N_0$ increases.

### 4.3 Part ب (Part 2 in Code) — Minimum $\ell_2$-Norm Solution (`Section1.m` lines 28–33)

Replacing the combinatorial $\ell_0$ pseudo-norm with the smooth Euclidean $\ell_2$-norm leads to the classical minimum-norm optimization problem:

```math
\hat{s}_{\ell_2} = \arg\min_{s \in \mathbb{R}^{60}} \|s\|_2^2
\qquad \text{subject to} \qquad
x = D s.
```

Because $D \in \mathbb{R}^{10 \times 60}$ has full row rank ($\mathrm{rank}(D) = 10$), the unique closed-form solution is given by the right Moore-Penrose pseudoinverse (`s_hat = pinv(D) * x`):

```math
\hat{s}_{\ell_2} = D^\dagger x = D^T \left(D D^T\right)^{-1} x \in \mathbb{R}^{60 \times 1}.
```

As shown in Figure 1 of the Persian report (Page 2), $\hat{s}_{\ell_2}$ spreads energy across **all $60$ entries** (with values oscillating densely between $-1.1332$ and $+1.7056$), producing a completely **non-sparse** vector. Because the $\ell_2$-norm penalizes large coefficients quadratically while placing a vanishingly small penalty on tiny coefficients, it favors distributing energy across all dictionary atoms rather than concentrating it on a few atoms.

**Role of knowing $N_0$:** Knowing $N_0$ **does not help at all** in this method, because the closed-form $\ell_2$-norm minimization $\hat{s}_{\ell_2} = D^\dagger x$ does not incorporate any cardinality constraint and inherently produces a dense $60 \times 1$ solution.

### 4.4 Part ج (Part 3 in Code) — Matching Pursuit (MP) (`Section1.m` lines 35–72)

**Matching Pursuit (MP)** is an iterative greedy algorithm that builds a sparse approximation one atom at a time by selecting, at each step $i$, the dictionary column $d_{\mathrm{ind}_i}$ having the largest projection onto the current residual $x_r$, and subtracting that single-atom projection from $x_r$:

1. Initialize the residual $x_r^{(0)} = x$ and the selected atom matrix $\hat{D} = [\,]$.
2. At iteration $i = 1, 2, \dots$:
   - Compute the inner products between the current residual $x_r^{(i-1)}$ and all dictionary columns (`[innerprodMax, ind] = max(x_r.' * D)`):

```math
\mathrm{ind}_i = \arg\max_{1 \le j \le N} \left( \left(x_r^{(i-1)}\right)^T d_j \right),
\qquad
\alpha_i = \left(x_r^{(i-1)}\right)^T d_{\mathrm{ind}_i}.
```

   - Append the selected atom to the active sub-dictionary: $\hat{D}(:, i) = d_{\mathrm{ind}_i}$.
   - Update the residual by subtracting the projection along $d_{\mathrm{ind}_i}$:

```math
x_r^{(i)} = x_r^{(i-1)} - \alpha_i d_{\mathrm{ind}_i}.
```

3. After selecting the atoms, compute the final least-squares coefficients on the selected sub-dictionary (`S_hat = pinv(D_hat) * x`) and evaluate the relative error $\mathrm{err} = \|x - \hat{D}\hat{S}\|_2 / \|x\|_2$.

- **Case 1 — Known Sparsity Level ($N_0 = 3$, lines 36–51, Pages 2–3 of the report):** Running the loop for exactly $N_0 = 3$ iterations selects atoms $(6, 3, 27)$ and yields:

```math
\hat{S}_{\mathrm{MP}} = \begin{bmatrix} 8.870176 \\ 4.840268 \\ 1.711150 \end{bmatrix},
\qquad
\mathrm{Err} = 0.16015,
\qquad
t_{\mathrm{exec}} = 0.003628\ \mathrm{s}.
```

- **Case 2 — Unknown Sparsity Level ($N_0$ unknown, lines 53–72, Page 3 of the report):** When $N_0$ is unknown, the loop runs up to `max_N_0 = size(D, 1) = 10` atoms and terminates via `break` as soon as the relative error satisfies $\mathrm{err} < \mathrm{err\_thr}$. With $\mathrm{err\_thr} = 10^{-1} = 0.1$:

```math
N_0 = 5 \text{ atoms},
\qquad
\mathrm{err} = 0.091557 < 0.1,
\qquad
t_{\mathrm{exec}} = 0.006297\ \mathrm{s}.
```

**Role of knowing $N_0$:** Knowing $N_0$ both **reduces execution time** ($0.003628\ \mathrm{s}$ vs. $0.006297\ \mathrm{s}$, avoiding repeated pseudoinverse/error evaluations inside the loop) and **determines the exact number of atoms** to extract ($N_0 = 3$ instead of over-selecting $5$ atoms to reach $\mathrm{err} < 10^{-1}$).

### 4.5 Part د (Part 4 in Code) — Orthogonal Matching Pursuit (OMP) (`Section1.m` lines 74–122)

In standard MP, subtracting only the single-atom projection $\alpha_i d_{\mathrm{ind}_i}$ makes the updated residual orthogonal only to the most recently chosen atom $d_{\mathrm{ind}_i}$, not to the previously chosen atoms $d_{\mathrm{ind}_1}, \dots, d_{\mathrm{ind}_{i-1}}$. Consequently, subsequent steps can re-introduce components along already-selected directions.

**Orthogonal Matching Pursuit (OMP)** overcomes this limitation by re-optimizing the coefficients of **all** previously selected atoms $\hat{D}_{\mathrm{pr}} = \hat{D}(:, 1:i)$ at every iteration $i > 1$ (`Section1.m` lines 82–88 and 105–111):

```math
\hat{s}_{\mathrm{pr}}^{(i)} = \hat{D}_{\mathrm{pr}}^\dagger x_r^{(i-1)},
\qquad
x_r^{(i)} = x_r^{(i-1)} - \hat{D}_{\mathrm{pr}} \hat{s}_{\mathrm{pr}}^{(i)}
= \left(I_M - \hat{D}_{\mathrm{pr}} \hat{D}_{\mathrm{pr}}^\dagger\right) x_r^{(i-1)}.
```

Because $I_M - \hat{D}_{\mathrm{pr}} \hat{D}_{\mathrm{pr}}^\dagger$ is the orthogonal projector onto $\mathrm{range}(\hat{D}_{\mathrm{pr}})^\perp$ and $x - x_r^{(i-1)} \in \mathrm{range}(\hat{D}_{\mathrm{pr}})$, the updated residual $x_r^{(i)} = (I_M - \hat{D}_{\mathrm{pr}} \hat{D}_{\mathrm{pr}}^\dagger) x$ is **strictly orthogonal to all $i$ selected atoms** $\hat{D}(:, 1:i)$.

- **Case 1 — Known Sparsity Level ($N_0 = 3$, lines 75–96, Page 3 of the report):** Running OMP for $N_0 = 3$ steps selects atoms $(6, 3, 22)$ and achieves a lower error than MP:

```math
\hat{S}_{\mathrm{OMP}} = \begin{bmatrix} 8.045944 \\ 4.837252 \\ 1.881823 \end{bmatrix},
\qquad
\mathrm{Err} = 0.15235,
\qquad
t_{\mathrm{exec}} = 0.003372\ \mathrm{s}.
```

- **Case 2 — Unknown Sparsity Level with $\mathrm{err\_thr} = 10^{-1}$ (lines 98–122, Page 4 of the report):**

```math
N_0 = 5 \text{ atoms},
\qquad
\mathrm{err} = 0.072322 < 0.1,
\qquad
t_{\mathrm{exec}} = 0.007541\ \mathrm{s}.
```

- **Case 3 — Stricter Error Threshold $\mathrm{err\_thr} = 10^{-2}$ Comparing MP vs. OMP (Page 4 of the report):** To highlight the structural advantage of orthogonal projection in OMP over standard MP, the stopping threshold in the Persian report (Page 4) is tightened from $10^{-1}$ to $\mathrm{err\_thr} = 10^{-2} = 0.01$:
  - **MP at $\mathrm{err\_thr} = 10^{-2}$:** Exhausts all `max_N_0 = 10` iterations without reaching the $10^{-2}$ threshold (because non-orthogonal updates cause MP to re-select atoms $27$ and $10$ twice among its $10$ steps), terminating at $N_0 = 10$ with $t_{\mathrm{exec}} = 0.006255\ \mathrm{s}$ and residual error $0.02424$ (printed as `0.002424` in the report bullet; see Section 5.3).
  - **OMP at $\mathrm{err\_thr} = 10^{-2}$:** Successfully drives the residual error below $10^{-2}$ using only **$N_0 = 8$ distinct atoms**, achieving $\mathrm{err} = 0.0048044 < 10^{-2}$ in $t_{\mathrm{exec}} = 0.007676\ \mathrm{s}$.

### 4.6 Part ه (Part 5 in Code) — Basis Pursuit (BP) via Linear Programming (`Section1.m` lines 124–137)

**Basis Pursuit (BP)** replaces the non-convex, NP-hard $\ell_0$ pseudo-norm with its closest convex envelope—the **$\ell_1$-norm**:

```math
\hat{s}_{\mathrm{BP}} = \arg\min_{s \in \mathbb{R}^N} \|s\|_1 = \sum_{n=1}^{N} |s_n|
\qquad \text{subject to} \qquad
x = D s.
```

To cast this non-differentiable $\ell_1$-minimization problem into a standard **Linear Programming (LP)** form (Page 5 of the report), decompose each real coefficient $s_n \in \mathbb{R}$ into its non-negative positive and negative parts:

```math
s_n = s_n^+ - s_n^-,
\qquad
|s_n| = s_n^+ + s_n^-,
\qquad
\begin{cases}
s_n^+ = \max(s_n, 0) \ge 0, \\
s_n^- = \max(-s_n, 0) \ge 0.
\end{cases}
```

*(Note: In the report's first display equation on Page 5, the decomposition over the arrow is written symbolically as $s_n = s_n^+ + s_n^-$, while the matrix equation immediately below it `[D -D] [s^+; s^-]` and line 129 of `Section1.m` `s = y(1:size(D,2)) - y(size(D,2)+1:end)` apply the exact difference $s = s^+ - s^-$.)*

Stacking $s^+ \in \mathbb{R}_+^{N \times 1}$ and $s^- \in \mathbb{R}_+^{N \times 1}$ into a single non-negative vector $y \in \mathbb{R}_+^{2N \times 1}$ ($2N = 120$) and defining the augmented dictionary $D_1 = \begin{bmatrix} D & -D \end{bmatrix} \in \mathbb{R}^{M \times 2N}$ ($10 \times 120$) yields the linear equality constraint:

```math
x = D s = D\left(s^+ - s^-\right)
= \begin{bmatrix} D & -D \end{bmatrix} \begin{bmatrix} s^+ \\ s^- \end{bmatrix}
= D_1 y,
\qquad
y = \begin{bmatrix} s^+ \\ s^- \end{bmatrix} \ge \mathbf{0}_{2N \times 1}.
```

Consequently, Basis Pursuit is equivalent to the standard Linear Program:

```math
\hat{y} = \arg\min_{y \in \mathbb{R}^{2N}} \mathbf{1}_{2N}^T y = \sum_{i=1}^{2N} y_i
\qquad \text{subject to} \qquad
D_1 y = x, \quad y_i \ge 0 \quad (\forall i = 1, \dots, 2N).
```

In `code/Section1.m` (lines 127–130), this LP is solved in a single call to MATLAB's `linprog`:

```matlab
D_1 = [D -D];
y = linprog(ones(1, size(D_1, 2)), [], [], D_1, x, zeros(1, size(D_1, 2)));
s = y(1:size(D, 2)) - y(size(D, 2) + 1:end);
S_hat = s(s ~= 0);
```

Extracting the non-zero entries of $s$ recovers the exact 3-sparse ground-truth vector (Page 5 of the report):

```math
\hat{S}_{\mathrm{BP}} = \begin{bmatrix} 5 \\ 7 \\ -3 \end{bmatrix},
\qquad
\mathrm{err} = 2.3272 \times 10^{-16} \approx 0,
\qquad
t_{\mathrm{exec}} = 0.009908\ \mathrm{s}.
```

**Is knowing $N_0$ necessary?** **No.** Basis Pursuit does not use $N_0$ anywhere in its formulation or solver; the geometry of the $\ell_1$-ball automatically drives the $57$ inactive components to zero and recovers the exact $3$ non-zero components.

### 4.7 Part و (Part 6 in Code) — Iteratively Reweighted Least Squares (IRLS) (`Section1.m` lines 139–160)

**Iteratively Reweighted Least Squares (IRLS)** solves the Basis Pursuit $\ell_1$-minimization problem by iteratively approximating the $\ell_1$-norm with a weighted $\ell_2$-norm (Pages 5–6 of the report):

```math
\|s\|_1 = \sum_{n=1}^{N} |s_n|
= \sum_{n=1}^{N} \frac{1}{|s_n|} |s_n|^2
\approx \sum_{n=1}^{N} w_n |s_n|^2 = s^T W s,
```

where $W = \mathrm{diag}(w_1, w_2, \dots, w_N) \in \mathbb{R}^{N \times N}$ is a diagonal weight matrix whose entries are updated from the previous iterate via

```math
w_n = \frac{1}{|s_n|}, \qquad n = 1, 2, \dots, N.
```

Holding $W$ fixed at a given iteration, we minimize the quadratic objective $f(s) = s^T W s$ subject to the linear equality constraint $x = D s$. Forming the Lagrangian with multiplier vector $\lambda \in \mathbb{R}^{M \times 1}$:

```math
\mathcal{L}(s, \lambda) = s^T W s - \lambda^T \left(D s - x\right),
```

and setting the gradient with respect to $s$ to zero gives:

```math
\nabla_s \mathcal{L}(s, \lambda) = 2 W s - D^T \lambda = 0
\quad \Longrightarrow \quad
\hat{s} = \frac{1}{2} W^{-1} D^T \lambda.
```

Substituting $\hat{s}$ into the constraint $D \hat{s} = x$ yields:

```math
\frac{1}{2} D W^{-1} D^T \lambda = x
\quad \Longrightarrow \quad
\lambda = 2 \left(D W^{-1} D^T\right)^{-1} x,
```

and substituting $\lambda$ back into $\hat{s}$ produces the closed-form weighted least-squares update rule:

```math
\boxed{
\hat{s} = W^{-1} D^T \left(D W^{-1} D^T\right)^{-1} x.
}
```

**Numerical Regularization / Weight Clamping (`Section1.m` lines 148–150):** As the algorithm converges, $57$ entries of $\hat{s}$ approach zero ($|s_n| \to 0$), causing their weights $w_n = 1 / |s_n|$ to diverge to $+\infty$ and making the matrix $W$ (and $D W^{-1} D^T$) poorly conditioned or numerically singular. To prevent division-by-zero and singular-matrix warnings in MATLAB, `Section1.m` clamps the weights at each of the `iterNum = 100` iterations:

```math
w_n = \begin{cases}
10^{-10}, & \text{if } |\hat{s}_n| > 10^3, \\[4pt]
10^{10}, & \text{if } |\hat{s}_n| < 10^{-3}, \\[4pt]
\dfrac{1}{|\hat{s}_n|}, & \text{otherwise}.
\end{cases}
```

After $100$ iterations, thresholding the recovered vector via `inds = find(abs(S_hat) > 1e-3)` isolates the exact support $(3, 6, 54)$ and recovers the ground-truth sparse coefficients (Page 6 of the report):

```math
\hat{S}_{\mathrm{IRLS}} = \begin{bmatrix} 5 \\ 7 \\ -3 \end{bmatrix},
\qquad
\mathrm{err} = 9.7861 \times 10^{-17} \approx 0,
\qquad
t_{\mathrm{exec}} = 0.011046\ \mathrm{s}.
```

**Is knowing $N_0$ necessary?** **No.** Like Basis Pursuit, IRLS operates on the full $60 \times 1$ vector $s$ and automatically suppresses the $57$ zero entries via the large weights $w_n = 10^{10}$ without requiring $N_0$.

### 4.8 Part ی — Multi-Criteria Comparison and Selection of the Best Method

On Page 6 of the Persian report, the six algorithms are compared across four engineering criteria:

1. **Reconstruction Accuracy (Error):** **Subset Selection** ($6.7605 \times 10^{-16}$), **Basis Pursuit (BP)** ($2.3272 \times 10^{-16}$), and **IRLS** ($9.7861 \times 10^{-17}$) all achieve exact recovery up to floating-point machine epsilon ($\mathrm{err} \approx 0$) and recover the true non-zero vector $[5, 7, -3]^T$. By contrast, **minimum $\ell_2$-norm** completely fails to produce a sparse vector, while **MP** ($\mathrm{err} = 0.16015$ at $N_0=3$) and **OMP** ($\mathrm{err} = 0.15235$ at $N_0=3$) suffer noticeable approximation errors due to their greedy atom-by-atom selection.
2. **Computational Speed:** **Subset Selection** is by far the slowest method ($1.084438\ \mathrm{s}$ for $N=60, N_0=3$) and scales combinatorially as $\binom{N}{N_0}$, making it impractical for large dictionaries or larger $N_0$. **MP**, **OMP**, **BP** ($0.009908\ \mathrm{s}$), and **IRLS** ($0.011046\ \mathrm{s}$) all execute in milliseconds ($\sim 3\text{–}11\ \mathrm{ms}$).
3. **Dependence on Prior Knowledge of $N_0$:** **Subset Selection**, **MP**, and **OMP** rely heavily on knowing $N_0$ (or require tuning an ad-hoc error threshold $\mathrm{err\_thr}$), whereas **BP** and **IRLS** require **no prior knowledge of $N_0$**.
4. **Algorithmic Structure (Direct Solver vs. Fixed-Iteration Loop):** Between the two top contenders (**BP** and **IRLS**), both offer machine-precision accuracy and millisecond runtimes without needing $N_0$. However, **Basis Pursuit (BP)** is **faster** ($0.009908\ \mathrm{s}$ vs. $0.011046\ \mathrm{s}$) and does not require choosing an arbitrary fixed outer loop count (`iterNum = 100`), random weight initialization, or heuristic weight clamping thresholds ($10^{\pm 10}$).

**Conclusion:** **Basis Pursuit (BP)** is selected as the **best overall algorithm** for sparse signal recovery in this assignment.

### 5.3 Notes on the Submitted Solutions / Implementation Notes

- **Signed vs. Magnitude Inner-Product Maximization in MP and OMP (`Section1.m` lines 41, 59, 80, 103):**
  - In `code/Section1.m`, the atom selection step in both MP and OMP is implemented as `[innerprodMax, ind] = max(x_r.' * D)` rather than maximizing the absolute correlation `max(abs(x_r.' * D))`.
  - Because the first two true coefficients are positive ($s_6 = +7$ and $s_3 = +5$), both MP and OMP correctly identify atoms **`ind = 6`** on Iteration 1 and **`ind = 3`** on Iteration 2. However, on Iteration 3, the residual is approximately $x_r^{(2)} \approx -3\, d_{54}$, whose inner product with the true third atom $d_{54}$ is negative ($\approx -3$). Because `max(x_r.' * D)` searches only for the largest **positive** inner product, it skips $d_{54}$ and instead selects positively correlated dictionary columns (atom `27` in MP and atom `22` in OMP), resulting in the non-zero residuals $\mathrm{Err}_{\mathrm{MP}} = 0.16015$ and $\mathrm{Err}_{\mathrm{OMP}} = 0.15235$ at $N_0 = 3$.
  - If ` [~, ind] = max(abs(x_r.' * D))` with signed projection `innerprodMax = x_r.' * D(:, ind)` is used, both MP and OMP select the exact support `[6, 3, 54]` in $3$ steps and recover $\hat{S} = [7, 5, -3]^T$ (permuted order of $[5, 7, -3]^T$) with machine-precision zero error ($\sim 10^{-16}$).
- **Incremental Residual Projection in OMP (`Section1.m` lines 83–85 and 106–108):**
  - On lines 83–85 of `Section1.m`, the OMP residual update for $i > 1$ is written as `D_pr = D_hat(:, 1:i); s_pr = pinv(D_pr) * x_r; x_r = x_r - D_pr * s_pr;`. Mathematically, because the difference $x - x_r^{(i-1)}$ already lies in the column space of $D_{\mathrm{pr}} = \hat{D}(:, 1:i)$ and $P_\perp = I - D_{\mathrm{pr}} D_{\mathrm{pr}}^\dagger$ is a linear orthogonal projection operator that annihilates $\mathrm{range}(D_{\mathrm{pr}})$, projecting the previous residual $x_r^{(i-1)}$ via $P_\perp x_r^{(i-1)}$ is **mathematically identical** to projecting the original observation vector $x$ via $P_\perp x = x - D_{\mathrm{pr}} (D_{\mathrm{pr}}^\dagger x)$.
- **Reconstruction Error Formula in Parts 5 & 6 (`Section1.m` lines 130–133 and 152–154):**
  - In Part 5 (Basis Pursuit, lines 130–131), `S_hat = s(s ~= 0)` extracts the $3 \times 1$ active vector $[5; 7; -3]$, and line 131 computes `D_hat = x * pinv(S_hat)` followed by `err_func = x - D_hat * S_hat`. Similarly, in Part 6 (IRLS, line 152), `D_hat = x * pinv(S_hat)` is used. Note that for any non-zero vector $v$, $(x v^\dagger) v = x (v^T v)/(v^T v) = x$ holds algebraically up to floating-point roundoff, whereas the physical dictionary reconstruction residual is `x - D * s` (in Part 5) and `x - D(:, inds) * s_hat` (in Part 6). Because both BP (`s`) and IRLS (`s_hat` on `inds = [3; 6; 54]`) recover the exact ground-truth coefficients $[5, 7, -3]^T$ to machine precision, the true dictionary residual $\|x - D \hat{s}\|_2 / \|x\|_2$ is also at the $10^{-16}$ machine-epsilon level ($\approx 3.62 \times 10^{-16}$).
- **Strict Inequality `s ~= 0` in Basis Pursuit (`Section1.m` line 130):**
  - Line 130 filters non-zero entries via `S_hat = s(s ~= 0)`. When `linprog` uses the dual-simplex algorithm, the $57$ inactive variables terminate at exact `0.0`, so `s(s ~= 0)` cleanly returns the $3 \times 1$ vector `[5; 7; -3]`. In newer MATLAB releases where `linprog` defaults to interior-point solvers, tiny numerical residuals ($\sim 10^{-12}$) may remain on inactive coordinates, so thresholding with `s(abs(s) > 1e-3)` (as done in Part 6 line 155) guarantees exact 3-element extraction across all solver settings.
- **Minor Typographical Slips in the Persian Report (Pages 4 and 5):**
  - On **Page 4 (Part د, comparison at $\mathrm{err\_thr} = 10^{-2}$)**, the narrative text correctly explains that MP fails to reduce the error below $\mathrm{err\_thr} = 10^{-2} = 0.01$ even after using all $N_0 = 10$ atoms, whereas the bullet above it prints the MP error with an extra leading zero as `0.002424` instead of the actual value `0.02424` ($> 0.01$).
  - On **Page 5 (Part ه, first display equation)**, the label above the second arrow in the constraint row is typed as `[D -D] = y , [s^+; s^-] = y` instead of `[D -D] = D_1 , [s^+; s^-] = y`, and the LP constraint is written with strict inequality $y_i > 0$ instead of $y_i \ge 0$ (which is properly passed as the lower bound `zeros(1, size(D_1, 2))` in `linprog` on line 128).
